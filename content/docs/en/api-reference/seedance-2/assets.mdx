Use this unified Seedance asset endpoint, **compatible with ByteDance / Volcengine Ark official formats**:

```text
POST /?Action=<operation>&Version=2024-01-01
```

Every operation uses **POST**, including queries, lists and deletion. JSON field names are case-sensitive: `GroupId`, `URL`, `AssetType`, `Name`, `ProjectName`. Read successful results from `Result` and request errors from `ResponseMetadata.Error`.

## Authentication

Send requests to `APIMETER_BASE_URL` with `Authorization: Bearer $APIMETER_API_KEY`. Use the same API base URL and API key as video tasks.

## Create an asset group

```bash
curl -X POST "$APIMETER_BASE_URL/?Action=CreateAssetGroup&Version=2024-01-01" \
  -H "Authorization: Bearer $APIMETER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"Name":"Video references","Description":"Virtual character references","GroupType":"AIGC"}'
```

Save `Result.Id` as the `GroupId`:

```json
{
  "ResponseMetadata":{"RequestId":"request-example","Action":"CreateAssetGroup","Version":"2024-01-01"},
  "Result":{"Id":"group-example"}
}
```

## Create an asset

```bash
curl -X POST "$APIMETER_BASE_URL/?Action=CreateAsset&Version=2024-01-01" \
  -H "Authorization: Bearer $APIMETER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "GroupId":"group-example",
    "URL":"https://example.com/reference.png",
    "AssetType":"Image",
    "Name":"Virtual character reference"
  }'
```

Use a public `URL` that remains accessible during processing, not Base64. `AssetType` is `Image`, `Video` or `Audio`.

Save the asset's `Result.Id`. Acceptance does not imply readiness. Additional fields such as `Status` depend on the actual response:

```json
{
  "ResponseMetadata":{"RequestId":"request-example","Action":"CreateAsset","Version":"2024-01-01"},
  "Result":{"Id":"asset-example"}
}
```

## Query asset status

```bash
curl -X POST "$APIMETER_BASE_URL/?Action=GetAsset&Version=2024-01-01" \
  -H "Authorization: Bearer $APIMETER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"Id":"asset-example"}'
```

```json
{
  "ResponseMetadata":{"RequestId":"request-example","Action":"GetAsset","Version":"2024-01-01"},
  "Result":{
    "Id":"asset-example",
    "GroupId":"group-example",
    "AssetType":"Image",
    "Name":"Virtual character reference",
    "Status":"Active",
    "URL":"https://example.com/reference.png"
  }
}
```

| `Result.Status` | Client behavior |
| --- | --- |
| `Processing` | Continue polling with an interval and overall timeout |
| `Active` | Ready for use in a video task |
| `Failed` | Stop and inspect `Result.Error.Code` / `Result.Error.Message` |
| `Expired` or other states | Verify availability; do not treat as `Active` |

HTTP 200/202 does not establish readiness. A successful query can report a failed asset. Official access URLs usually expire; preserve asset IDs for long-term references.

## Actions and request bodies

All bodies may include `ProjectName`. Match the `Action` query parameter to the selected body.

| Action | Purpose | Example body |
| --- | --- | --- |
| `CreateAssetGroup` | Create group | `{"Name":"References","Description":"","GroupType":"AIGC"}` |
| `GetAssetGroup` | Get group | `{"Id":"group-example"}` |
| `ListAssetGroups` | List groups | `{"Filter":{"GroupType":"AIGC"},"MaxResults":20}` |
| `UpdateAssetGroup` | Update name/description | `{"Id":"group-example","Name":"New name","Description":"New description"}` |
| `DeleteAssetGroup` | Delete group | `{"Id":"group-example"}` |
| `CreateAsset` | Create asset | `{"GroupId":"group-example","URL":"https://example.com/reference.png","AssetType":"Image","Name":"Reference"}` |
| `GetAsset` | Get asset | `{"Id":"asset-example"}` |
| `ListAssets` | List assets | `{"Filter":{"GroupType":"AIGC","GroupIds":["group-example"]},"MaxResults":20}` |
| `UpdateAsset` | Rename asset | `{"Id":"asset-example","Name":"New name"}` |
| `DeleteAsset` | Delete asset | `{"Id":"asset-example"}` |
| `CreateVisualValidateSession` | Create verification session | `{"CallbackURL":"https://example.com/callback"}` |
| `GetVisualValidateResult` | Get verification result | `{"BytedToken":"<session-token>"}` |

Verification sessions return `Result.H5Link` and `Result.BytedToken`. The user opens `H5Link` to complete verification. Then query the result with `BytedToken` and save the returned group information.

Lists return `Result.Items` and pagination fields. Use either `MaxResults/NextToken` or `PageNumber/PageSize`, never both, with at most 100 items per page. Pass the previous response's `Result.NextToken` unchanged for the next page. Lists contain only assets accessible to the current user.

Updates and JSON deletion responses use `ResponseMetadata + Result`; successful deletion has `Result: {}`. HTTP 204 indicates success without a body. Check the target ID before deletion; deleting a group may affect its assets.

## Errors

```json
{
  "ResponseMetadata":{
    "RequestId":"request-example",
    "Action":"GetAsset",
    "Version":"2024-01-01",
    "Error":{"Code":"asset_not_found","Message":"asset not found"}
  }
}
```

Check both HTTP status and `ResponseMetadata.Error`, including on HTTP 200. Use `Error.Code` and `Error.Message` to check parameters, resource IDs or access permissions. For 429/503 responses, follow `Retry-After` before retrying queries.

Do not blindly repeat creation after a timeout or malformed response. Keep the request ID for diagnosis and preserve asset IDs to resume queries.

## Use an asset in a video

Append the asset's `Result.Id`, not its GroupId, to `asset://`. Use an `Active` asset that your account can access, including its project:

```json
{
  "model":"doubao-seedance-2-0-260128",
  "content":[
    {"type":"text","text":"The virtual character in image 1 walks through a garden"},
    {"type":"image_url","image_url":{"url":"asset://asset-example"},"role":"reference_image"}
  ],
  "resolution":"720p",
  "ratio":"16:9",
  "duration":5,
  "generate_audio":true,
  "watermark":false
}
```

Submit to `POST /api/v3/contents/generations/tasks`. Video and audio assets use `video_url.url` and `audio_url.url`; see [Modes](./modes).

## Native video-task input limits

These limits apply to `content[]` in Seedance 2.0 video tasks. Library image ingestion requirements follow the table.

| Media | Sources and formats | Seedance 2.0 limits |
| --- | --- | --- |
| Image | jpeg/png/webp/bmp/tiff/gif/heic/heif; public URL, Data URL, usable asset URI | Under 30 MB each; aspect ratio [0.4, 2.5]; width and height [300, 6000] px; up to 9 reference images |
| Video | mp4/mov; public URL or usable asset URI; no Base64 | 2–15 seconds each, up to 3 totaling at most 15 seconds; at most 200 MB each; 24–60 FPS |
| Audio | wav/mp3; public URL, Data URL, usable asset URI | 2–15 seconds each, up to 3 totaling at most 15 seconds; at most 15 MB each; requires image/video |

Reference videos support 480p/720p/1080p/4k. Aspect ratio is [0.4, 2.5], each dimension [300, 6000] px, and pixel count [407696, 8295044]. MP4/MOV support H.264/AVC and H.265/HEVC; see the official API for audio codecs.

The video-task request body limit is 64 MB. Use URLs for large files. Private-library image ingestion accepts jpeg/png/webp/tiff/gif/heic/heif, with aspect ratio (0.4, 2.5), dimensions (300, 6000) px, and under 30 MB.
