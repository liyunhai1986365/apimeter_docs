## Choose the media workflow

Ordinary non-portrait references may use public URLs directly; not all media needs to enter the private library. The private virtual portrait library is for virtual portraits. Real-person portraits require a separate authorization process. Preset portraits and trusted model outputs follow the [official portrait guide](https://docs.volcengine.com/docs/ark/seedance-portrait-asset-guide?lang=zh).

## Upload an asset

Only public URLs are supported here, not Base64. Keep the source accessible throughout asynchronous processing. Type values are case-sensitive: `Image`, `Video`, `Audio`.

For the existing overseas channel, append `?model=dreamina-seedance-2-0-fast-260128` to both upload and detail requests. Domestic routes omit it under the platform's existing contract. This is platform channel selection, not an official CreateAsset parameter.

Check business `code` and save `data.Id`; upload success does not mean the asset is ready. Parameters, examples and live debugging:

## Query asset status

Use the returned `data.Id` as path parameter `id`. Use the same `model` query parameter for overseas upload and lookup.

<ApiPlaygroundEmbed href="/docs/api-reference/视频系列/getSeedanceAsset" title="Get asset · GET /api/assets/{id}" />

| `data.Status` | Action |
| --- | --- |
| `Processing` | Keep polling |
| `Active` | Ready for video generation |
| `Failed` | Stop and inspect the result |

HTTP success is not business success or readiness. Ingestion has no official processing-time SLA; bound polling and preserve the ID to resume.

## Reference an active asset

Use `asset://<asset_id>`, not the GroupId, in the matching `image_url.url`, `video_url.url`, or `audio_url.url` field.

```json
{
  "model": "doubao-seedance-2-0-260128",
  "content": [
    {"type":"text","text":"The virtual character in image 1 walks through a garden"},
    {"type":"image_url","image_url":{"url":"asset://asset-20260325152211-vcchd"},"role":"reference_image"}
  ],
  "resolution":"720p",
  "ratio":"16:9",
  "duration":5,
  "generate_audio":true,
  "watermark":false
}
```

Prompts reference media by type and order within that type, starting at 1; never put asset IDs in prompts. Generic format uses `image`/`images[]`, `metadata.video_url`, and `metadata.audio_url`. Assets are not guaranteed portable across accounts or channels.

Real-person authorization is separate: this project defines `/api/resource-channel/byteplus/visual-validate/...` operations for verification sessions and portrait management. Ordinary upload does not replace authorization.

If an asset fails, check business code, status, media type, asset versus group ID, matching model route, and project/account permissions.

## Official API versus platform wrapper

| Item | Official Ark control plane | Platform |
| --- | --- | --- |
| Upload | CreateAsset after CreateAssetGroup | `POST /api/assets/upload` |
| Query | GetAsset | `GET /api/assets/{id}` |
| Authentication | AK/SK signing and IAM | Platform Bearer API key |
| Fields | `GroupId`, `URL`, `AssetType`, `Name`, `ProjectName` | `url`, `asset_type`, `name` |
| Returned asset ID | `Result.Id` | `data.Id` |

Official asset APIs use `https://ark.cn-beijing.volcengineapi.com/`, a different host from video generation. CreateAsset uses `POST /?Action=CreateAsset&Version=2024-01-01`. GetAsset also uses **POST**: `POST /?Action=GetAsset&Version=2024-01-01`, with `Id` and optional `ProjectName` in the JSON body. The platform's `GET /api/assets/{id}` is a separate contract.

Official GetAsset `Result.URL` is an access URL valid for 12 hours and need not equal the original upload URL. Preserve the asset ID and reference `asset://<asset_id>` for reuse. HTTP 200 may still describe a failed asset: inspect `Result.Status` and `Result.Error.Code` / `Result.Error.Message`. Platform passthrough of these additional fields depends on its actual response.

Official assets and groups must share a ProjectName, and generation must use an API key in that project. Official library entitlements, capacity and quotas are account-dependent. Platform resources are channel-dependent. Official list/update/delete operations are not established platform REST routes.

## Native video-task input limits

These are inference limits, not a guarantee about platform upload limits or overseas channels.

| Media | Sources and formats | Seedance 2.0 limits |
| --- | --- | --- |
| Image | jpeg/png/webp/bmp/tiff/gif/heic/heif; public URL, Data URL, usable asset URI | Under 30 MB each; aspect ratio [0.4, 2.5]; width and height [300, 6000] px; up to 9 reference images |
| Video | mp4/mov; public URL or usable asset URI; no Base64 | 2–15 seconds each, up to 3 totaling at most 15 seconds; at most 200 MB each; 24–60 FPS |
| Audio | wav/mp3; public URL, Data URL, usable asset URI | 2–15 seconds each, up to 3 totaling at most 15 seconds; at most 15 MB each; requires image/video |

Reference videos support 480p/720p/1080p/4k. Aspect ratio is [0.4, 2.5], each dimension [300, 6000] px, and pixel count [407696, 8295044]. MP4/MOV support H.264/AVC and H.265/HEVC; see the official API for audio codecs.

The native request body limit is 64 MB. Use URLs for large files; the former 2 MB Base64 rule is obsolete. Private-library ingestion has separate image rules: jpeg/png/webp/tiff/gif/heic/heif, aspect ratio (0.4, 2.5), dimensions (300, 6000) px, and under 30 MB.
