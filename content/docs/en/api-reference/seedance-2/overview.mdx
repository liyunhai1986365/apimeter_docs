title: Seedance API (Official Format)
description: Unified Seedance video and asset APIs, with authentication, request parameters, responses and examples.
---

Seedance video generation and asset management use a unified API **compatible with ByteDance / Volcengine Ark official formats**. Use the same API base URL and API key for every request. Video tasks use `content[]`; assets use `Action` requests and `ResponseMetadata + Result` responses.

## Endpoints and authentication

| Operation | Method and path | Result fields |
| --- | --- | --- |
| Create video task | `POST /api/v3/contents/generations/tasks` | `id` |
| Query video task | `GET /api/v3/contents/generations/tasks/{task_id}` | `status`, `content.video_url` |
| Manage assets and asset groups | `POST /?Action=<operation>&Version=2024-01-01` | `ResponseMetadata`, `Result` |

Use `Authorization: Bearer $APIMETER_API_KEY`. Set `APIMETER_BASE_URL` to the API root, without `/api/v3`. Assets and video tasks use the same Bearer authentication. See [Assets — Official Format](./assets) for creating, managing and referencing assets.

## Models and output

Set `model` to a Seedance model ID or alias available to your account. Models use the same task endpoints; choose parameters according to the selected model's specifications.

The basic examples use Seedance 2.0:

| Model | Example ID | Official 2.0 resolutions |
| --- | --- | --- |
| Seedance 2.0 | `doubao-seedance-2-0-260128` | `480p`, `720p`, `1080p`, `4k` |
| Seedance 2.0 Fast | `doubao-seedance-2-0-fast-260128` | `480p`, `720p` |

Standard-model 4k uses 10bit H.265/HEVC. Fast does not support 1080p or 4k. For other models, use their documented resolutions, durations and features.

## Create and query a video

```bash
curl -X POST "$APIMETER_BASE_URL/api/v3/contents/generations/tasks" \
  -H "Authorization: Bearer $APIMETER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seedance-2-0-260128",
    "content": [{"type":"text","text":"A dog runs beneath cherry blossoms"}],
    "resolution": "720p",
    "ratio": "16:9",
    "duration": 5,
    "generate_audio": true,
    "watermark": false
  }'
```

Creation returns at least an `id`. Save it exactly, without assuming a prefix, status or video URL:

```json
{"id": "<TASK_ID>"}
```

```bash
curl "$APIMETER_BASE_URL/api/v3/contents/generations/tasks/$TASK_ID" \
  -H "Authorization: Bearer $APIMETER_API_KEY"
```

Successful query example:

```json
{
  "id": "<TASK_ID>",
  "status": "succeeded",
  "model": "doubao-seedance-2-0-260128",
  "content": {"video_url": "https://example.com/result.mp4"},
  "usage": {"completion_tokens": 100858, "total_tokens": 100858},
  "error": null
}
```

## Request parameters

Put options at the JSON top level and media in `content[]`. Values such as `0`, `false` and `-1` follow each parameter's definition. Omitted options use model defaults.

| Field | Meaning |
| --- | --- |
| `model`, `content` | Model and content array; basic media types are `text`, `image_url`, `video_url`, `audio_url` |
| `resolution`, `ratio` | Output resolution and aspect ratio; 2.0 defaults to `720p`, `adaptive` |
| `duration` | 2.0 uses integer 4–15 seconds; use `-1` for models supporting automatic duration |
| `generate_audio`, `watermark` | 2.0 defaults to `true`, `false`; examples supply both explicitly |
| `return_last_frame` | Request a last frame; read `content.last_frame_url` when returned |
| `callback_url` | Publicly reachable callback URL |
| `execution_expires_after` | Server execution expiry in seconds, official range 3600–259200 |
| `priority`, `safety_identifier`, `tools` | Priority, safety identifier and tools; `web_search` support depends on the model |
| `seed`, `frames`, `camera_fixed`, `draft`, `service_tier` | Random seed, frame count, fixed camera, draft mode and service tier; use according to model specifications |
| `output_format`, `omni_reference_task_type` | For models supporting these options; 2.5 task types are `auto`, `reference`, `edit`, `extend` |

`edit` requires `duration=-1`, `ratio=adaptive` and a `reference_video`; `extend` requires `ratio=adaptive` and a reference video. The 2.0 examples express editing and extension through prompts instead.

Seedance 2.0 does not support draft mode or flex inference. Omit `seed`, `frames` and `camera_fixed` in 2.0 requests. See the video generation reference for detailed fields.

## Inputs and task lifecycle

For 2.0, first-frame, first/last-frame and multimodal reference modes are mutually exclusive. References allow up to 9 images, 3 videos and 3 audio clips; audio requires an image or video. See [Modes](./modes) and [Assets](./assets).

| `status` | Client behavior |
| --- | --- |
| `queued`, `running` | Continue polling |
| `succeeded` | Read `content.video_url`; save last-frame and usage fields when needed |
| `failed`, `expired`, `cancelled`, `canceled` | Stop polling and inspect `error`; the last two indicate cancellation |

Query responses include task status, result URLs and `usage` details. Successful `error` may be `null`.

Query results within 7 days of task creation and download promptly after completion; video URLs usually expire after 24 hours. Stopping client polling does not cancel the server task. See [Python polling and download](./python-polling).
