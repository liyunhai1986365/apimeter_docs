CC Switch can manage providers, base URLs, API keys, and model settings for Claude Code, Codex, Gemini CLI, OpenClaw, Hermes, and other AI tools. In most cases, you only need to point `BASE_URL` to your OpenAI-compatible API endpoint and use an API key generated by the current site.

## Three-Step Setup

1. Sign in to the console and create or copy your API key.
2. Use separate keys for different users or projects so usage, revocation, and troubleshooting stay clear.
3. Set the client's `BASE_URL` to the current site's API endpoint, for example `MODELSELL_API_BASE_URL`.

## Console Import

If your console supports the CC Switch deep link, open the token management page and choose the CC Switch shortcut. The site will launch CC Switch and open the setup dialog.

![Fill the CC Switch dialog](/assets/docs/apps/cc_switch/fill_dialog_zh.png)

After confirming the app type, profile name, default model, and API key, click open CC Switch. The client will show an import confirmation dialog.

![Confirm the CC Switch import](/assets/docs/apps/cc_switch/confirm_import_zh.png)

Click import to write the profile into CC Switch. You can then switch providers for Claude, Codex, Gemini, and other apps inside CC Switch.

## Node.js Environment

Codex, Gemini CLI, OpenClaw, and Hermes commonly rely on Node.js. Check your local environment first:

```bash
node --version
npm --version
```

macOS:

```bash
brew install node
```

Windows:

```powershell
winget install OpenJS.NodeJS.LTS
```

Linux / WSL:

```bash
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt-get install -y nodejs
```

## Setup Scripts

These scripts prompt for your API key locally and generate CC Switch configuration for the selected tool. The copied command itself does not contain your secret.

### Codex Windows

Writes to `~/.codex/config.toml` and uses an OpenAI-compatible `/v1` base URL.

```powershell
irm https://ccswitch.cc/install/codex.ps1 | iex
```

### Codex macOS / Linux / WSL

Checks Node.js and Codex CLI, then prompts you to install missing tools if needed.

```bash
curl -fsSL https://ccswitch.cc/install/codex.sh | bash
```

### OpenClaw

Prompts you to choose the Claude or OpenAI/Codex channel and generates a CC Switch configuration reference.

```bash
curl -fsSL https://ccswitch.cc/install/openclaw.sh | bash
```

### Hermes

Prompts for the channel and generates a reusable CC Switch provider profile.

```bash
curl -fsSL https://ccswitch.cc/install/hermes.sh | bash
```

## Python Example

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-your-api-key",
    base_url="MODELSELL_API_BASE_URL",
)

response = client.chat.completions.create(
    model="gpt-5.3-codex",
    messages=[{"role": "user", "content": "Hello!"}],
)

print(response.choices[0].message.content)
```

## curl Example

```bash
curl MODELSELL_API_BASE_URL/chat/completions \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.3-codex",
    "messages": [
      { "role": "user", "content": "Hello!" }
    ]
  }'
```

## Node.js Example

The official OpenAI SDK uses the `baseURL` field:

```ts
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: "sk-your-api-key",
  baseURL: "MODELSELL_API_BASE_URL",
});

const response = await client.chat.completions.create({
  model: "gpt-5.3-codex",
  messages: [{ role: "user", content: "Hello!" }],
});

console.log(response.choices[0].message.content);
```

## Supported Tool Integrations

### OpenClaw

Use an API URL without `/v1` for the Claude / Anthropic channel. Use the OpenAI-compatible `/v1` base URL for OpenAI / Codex channels.

### Claude Code

If your account has Claude or compatible upstream access enabled, use the configuration shown in the console.

### OpenAI Codex

Clients that support custom endpoints can connect by changing `BASE_URL`.

### Gemini CLI

Set `GOOGLE_GEMINI_BASE_URL`, `GEMINI_API_KEY`, and `GEMINI_MODEL`.

### Cursor

Fill in the custom API address, API key, and available model names in settings.

### Hermes

Use the setup script to generate address, key, and model values, then copy them into the provider settings for your Hermes version.

## Gemini CLI Environment Variables

macOS / Linux / WSL:

```bash
export GOOGLE_GEMINI_BASE_URL="MODELSELL_API_ORIGIN"
export GEMINI_API_KEY="sk-your-api-key"
export GEMINI_MODEL="gemini-3-pro-preview"

gemini -p "Hello"
```

Windows PowerShell:

```powershell
$env:GOOGLE_GEMINI_BASE_URL = "MODELSELL_API_ORIGIN"
$env:GEMINI_API_KEY = "sk-your-api-key"
$env:GEMINI_MODEL = "gemini-3-pro-preview"

gemini -p "Hello"
```

## Codex Config Snippet

The setup script writes an equivalent configuration. If you configure it manually, keep your own API key and available model name.

```toml
model_provider = "ccswitch"
model = "gpt-5.3-codex"
preferred_auth_method = "apikey"

[model_providers.ccswitch]
name = "CC Switch"
base_url = "MODELSELL_API_BASE_URL"
wire_api = "responses"
experimental_bearer_token = "sk-your-api-key"
requires_openai_auth = true
```

## Notes

| Item | Details |
| --- | --- |
| Base URL | OpenAI-compatible clients should use the API address that ends with `/v1`. Do not use the console URL as the API base URL unless it is also your API endpoint. |
| API Key | Use a user token generated by the current site's console. Do not paste keys from OpenAI, Claude, Gemini, or other upstream platforms. |
| Model name | Prefer the exact model IDs returned by `GET /v1/models`. Visible models may vary by key. |
